What This Changes

What the backend considers valid

This tab defines the contract for language packs: which sections are required, which names are allowed, and how strict validation should be.

Suggested Workflow

Adjust contract carefully

Only edit the schema when you want to broaden or tighten what a language pack is allowed to contain. Most language design work belongs in `Rules JSON`, not here.

3. Allowed Names

These lists define which resolver and segmenter names the backend should recognize as valid.

This is an advanced contract file. If you only want to change how one language behaves, `Rules JSON` is usually the better place.

How it behaves

English to the loaded language remains a best-effort generator based on the active lexicon.

Loaded-language parsing now tries normalization, affix splitting, compound recovery, drift rescue, glossing, and idiomatic line reading.

Poetic overrides preserve ritual lines without flattening the underlying morpheme analysis.

Lexicon File

The translator now reads vocabulary from data/lexicon.json.

Rules and notes are loaded from data/rules-notes.md and included in the markdown export.

You can also import any compatible JSON lexicon file with the control above when you want to swap datasets without editing the code.

Use { "confirmed": [...], "inferred": [...] } or a plain array for confirmed entries only.

If you open the page directly from disk and the browser blocks JSON loading, run start-translator.bat to serve it locally without cross-origin issues.
